⚠ Portal error “Predicted values must be in range [0, 1]” — cause and fix

DrivenData requires every predicted value in [0,1] (official submission format, problem page 967, re-verified 2026-10-21). The usual trigger in this project family is the float32 sentinel -3.4028234663852886e+38: training_features.tif uses it as nodata, and any pipeline that writes it through (as data or as a nodata tag a validator reads as a value) fails the range check.

Fix applied to every file above: written all-finite with nodata=None and 0.0 outside the footprint, then re-opened from disk and checked cell-by-cell (all 12,279,160 cells finite, min ≥ 0, max ≤ 1, 0 NaN) by the shared validator before delivery. Each file ships its re-read receipt. If you ever see the error, you have picked a stale/sentinel file — re-download the -zeros/all-finite file from this page.
